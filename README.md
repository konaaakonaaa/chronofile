# chronofile

Локальная «машина времени» для файлов — без сторонних зависимостей.

`chronofile` следит за папкой и автоматически сохраняет каждую версию
каждого файла — как Git, но без ручных коммитов и работает для *любых*
файлов (черновики, конфиги, картинки), а не только для кода.

Никаких внешних библиотек. Никакого сервера. Только скрытая папка
`.chronofile/` рядом с вашими файлами.

## Зачем это нужно

Ctrl+Z откатывает только последнее действие. Git требует не забывать
коммитить. Системные «истории версий» (Time Machine, File History) — это
тяжеловесные решения на уровне всей ОС. А иногда просто хочется: «как
выглядел этот файл час назад, и можно ли его вернуть?» — для одной папки,
без настройки.

## Как это устроено

- **Контентно-адресуемое хранилище** — та же идея, что и в Git: каждая
  уникальная версия содержимого файла хэшируется (SHA-1) и сохраняется один
  раз, в сжатом виде, в `.chronofile/objects/`. Одинаковое содержимое в
  разных файлах или ревизиях автоматически дедуплицируется.
- **SQLite** хранит человекочитаемую хронологию: путь, номер ревизии, хэш,
  время, сообщение.
- **Демон-наблюдатель** на поллинге (без зависимостей вроде `inotify`/
  `watchdog` — чистый stdlib, одинаково работает на Linux/macOS/Windows)
  делает снапшот изменённых файлов через заданный интервал.

## Установка

```bash
git clone https://github.com/konaaakonaaa/chronofile.git
cd chronofile
pip install -e .
```

(Либо просто запускать на месте через `python -m chronofile ...` — сторонних
зависимостей нет вообще.)

## Использование

```bash
# Начать отслеживание текущей папки
chronofile init

# Сделать снапшот вручную прямо сейчас
chronofile snapshot -m "перед тем как всё сломаю"

# Или пусть следит и снапшотит сам
chronofile watch --interval 5

# Что изменилось с последнего снапшота
chronofile status

# Полная история одного файла
chronofile log notes.txt

# Diff между любыми двумя ревизиями (номера, либо -1/-2 = "последняя"/"предпоследняя")
chronofile diff notes.txt 1 3

# Показать файл таким, каким он был в ревизии 2
chronofile show notes.txt 2

# Откатить файл (текущая версия автоматически бэкапится перед откатом)
chronofile restore notes.txt 1
```

Ревизию можно указывать:
- абсолютным номером (`1`, `2`, `3`, ...)
- относительным индексом с конца (`-1` = последняя, `-2` = предпоследняя)
- префиксом хэша (`chronofile diff notes.txt 09fac8 -1`)

## Игнорирование файлов

В `.chronofile/config.json` есть список `ignore` с glob-паттернами (по
умолчанию: `.git`, `node_modules`, `__pycache__`, `*.tmp` и т.п.). Отредактируйте
под свой проект.

## Идея дизайна

Проект намеренно переизобретает небольшой кусочек внутренностей Git
(контентно-адресуемые блобы + журнал версий), но применяет это непрерывно и
автоматически к обычной папке, без явных `add`/`commit` на каждое изменение —
это ближе к истории версий а-ля Dropbox, чем к VCS, с которой работают вручную.
